# InstituteGPT Advance — Canonical Learning, Skills & Advancement Architecture

**Status: CANONICAL DESIGN — 2026-09-06**

## 1. Product position

`InstituteGPT → Advance`

Advance is the first-class InstituteGPT service for universal learning, skills development, courses, learning paths, practical learning, labs, CPD, professional learning, badges, certificates and advancement.

Advance is not a standalone LMS. It composes the canonical InstituteGPT education layer and OMNII common capabilities.

## 2. First-class boundary

Advance owns the learner-facing progression composition:

`learning + courses + learning paths + skills + competencies + labs + practice + projects + CPD + professional learning + badges + certificates + credential references + lifelong advancement`

Supporting functions remain reusable InstituteGPT education capabilities:

`discovery, counselling, admissions, curriculum, teaching, tutoring, mentoring, coaching, accessibility, assessment, examinations, marking, invigilation/proctoring, learner success, wellbeing, research, libraries, work-integrated learning, administration, interoperability, funding, government education and AI governance`.

Labs, Learning Wallet, Skills Passport, Pathway Builder and Education Marketplace are capabilities inside Advance at this stage rather than separate top-level products.

## 3. InstituteGPT family

`InstituteGPT`
`├── Advance — learning, skills, credentials and advancement`
`├── OpenEd Bot — open/distance/flexible education composition`
`├── Notebook — study/research/teaching/evidence workspace`
`└── Exams — examination and formal testing product`

These products compose one education layer and may invoke each other without duplicating semantics.

## 4. Universal learner coverage

Advance supports:

`early childhood → primary → secondary → youth → vocational/technical → tertiary → postgraduate → doctoral → professional entry → workplace → career transition → entrepreneurship → professional development → lifelong learning`

It also supports governed AI/agent learning as a distinct learner type.

A child uses the same semantic education substrate with age-appropriate content, consent, safeguarding, privacy, communications, data retention and supervision rules. Childhood learning does not silently become a permanent adult employment record.

## 5. Universal value chain

`discover → identity/context → goal → diagnose → advise → plan → select path → learn → practice → lab/simulation → project → experience → demonstrate → assess → recognize → badge/certificate/credential → portfolio/record → opportunity → work/practice → CPD → renew/recertify → reskill/upskill → lifelong learning`

The path is a graph, not a fixed linear sequence. Stages can repeat, branch, stack, be skipped or be entered through recognition of prior learning.

## 6. Learning Experience

The fundamental learning unit is a **Learning Experience** rather than a course-only object.

A Learning Experience may contain:

`lesson, reading, media, AI dialogue, teaching, tutoring, exercise, quiz, discussion, lab, simulation, project, fieldwork, mentorship, apprenticeship, internship and assessment`

Learning experiences are versioned, prerequisite-aware, accessible, localizable and mappable to outcomes and competencies.

## 7. Courses and programmes

Advance supports:

`microlearning, lesson, module, short course, certificate course, diploma course, specialization, professional programme, bootcamp, ExpertTrack-style sequence, CPD activity, apprenticeship, internship, work-based programme, community course and lifelong-learning programme`.

Courses are one delivery form. A learner may receive a path assembled from multiple providers and modalities.

## 8. Learning paths

A Learning Path contains:

`goal + starting capability + prerequisites + experiences + skills + competencies + labs + projects + assessments + credential outcomes + opportunity targets + renewal branches + provenance + version`

Paths can be:

`native | partner | institutional | employer | professional-body | government | learner-authored | AI-generated`

AI-generated paths must remain governed recommendations where educational or high-impact decisions require human authority.

## 9. Skills and competencies

Advance distinguishes:

`knowledge → skill → competency → demonstrated competency → achievement → qualification → professional authorization`

It also distinguishes skill states:

`self-declared | learning | practiced | assessed | demonstrated | externally verified | expired | superseded`

A course does not automatically prove mastery. A badge does not automatically grant regulated professional authority.

## 10. Labs

Labs are a core Advance capability because they connect learning to demonstrated capability.

Supported lab classes include:

`coding, cloud, AI, data, cybersecurity, science, engineering, robotics, electronics, medicine, agriculture, manufacturing, finance, GIS, media, design, language, vocational, field, simulation, VR/AR, digital twin, hardware-connected and remote`

Runtime forms include:

`sandbox, browser environment, notebook, container, virtual machine, cloud workspace, remote hardware, simulation engine and physical facility`

A lab can emit:

`artifacts, completion evidence, assessment signals, project evidence and competency demonstrations`.

## 11. Practice, projects and evidence

Advance supports deliberate practice, problem-based learning, scenario exercises, project work, team work, portfolios and supervised experience.

Evidence remains distinct from assessment and authoritative credentialing.

## 12. CPD and professional learning

CPD is a core Advance capability:

`activity → competency → learning outcome → evidence → hours/credits → assessment → completion → professional framework → renewal/relevance`

Professional bodies remain authoritative for mandatory CPD rules, certifications, recertification and licenses.

Professional learning can cover entry, specialization, refresher learning, competence maintenance, leadership and career transition.

## 13. Badges, certificates and credentials

Advance recognizes a continuum:

`participation → completion → badge → microcredential → certificate → professional certificate → diploma → degree reference → qualification → professional certification → regulated authorization`

Issuer authority is preserved.

Advance may issue configured ecosystem-native credentials and may record/reference external credentials. It may not represent an internal achievement as an external regulator, professional body or university credential.

## 14. Digital credentials

Interoperability targets include:

`1EdTech Open Badges 3.x + CLR 2.x + W3C Verifiable Credentials 2.0`

Achievement records should retain, where supported:

`issuer, earner, achievement, criteria, evidence, framework alignment, endorsement, provenance, issue date, expiry and verification state`.

## 15. Learning Wallet

Learning Wallet is an Advance capability for the portable collection/reference of:

`learning activities, achievements, badges, certificates, credentials, transcripts, assessments, projects and evidence`.

It should be exportable and provider-neutral.

## 16. Skills Passport

Skills Passport is a provenance-aware view of:

`declared + learned + practiced + assessed + demonstrated + externally verified skills`

It can map skills to occupations, competency frameworks, programmes and opportunities without replacing any external taxonomy.

## 17. Pathway Builder

Pathway Builder allows learners and authorized organizations to compose:

`goal → skills → learning → practice → evidence → credential → opportunity`

Inputs may include diagnostics, competency frameworks, credential prerequisites, occupation requirements and employer needs.

## 18. Education Marketplace

Marketplace capability discovers native, partner and external learning without absorbing provider authority.

Provider ownership remains visible. Learning, credential and pricing information is sourced only through authorized or publicly available provider interfaces.

## 20. Technology and AI learning

AI learning may include:

`AI awareness → AI literacy → prompting → AI productivity → workflows → agents → tool use → MCP → retrieval → evaluation → safety/security → AI products → AI engineering → research → governance → leadership`

Technology versions remain external, versioned knowledge/skills mappings so the architecture can absorb future standards without amendment.

## 21. Human and AI learners

Human and AI learners remain distinct.

AI learners may:

`receive knowledge packages → study → practice → simulate → benchmark → undergo capability assessment → update capability state → prepare for deployment`

AI learning does not become human education automatically; human credentials do not automatically authorize AI deployment or professional practice.

## 22. Child learning

Child pathways use the same learning graph with additional governance for:

`age suitability, guardian consent, teacher supervision, privacy, safety, communications, discovery, advertising/profiling restrictions, data retention and credential visibility`.

Child-focused learning can cover literacy, numeracy, science, arts, languages, coding, digital literacy, AI literacy, financial literacy, civic learning, creativity, entrepreneurship and practical skills.

## 23. Education roles

Advance composes:

`learner | teacher | tutor | mentor | coach | parent/guardian | counsellor | researcher | administrator | professional supervisor | examiner | employer | institution | government`

A role may be human, organizational or governed AI where the relevant action is permitted.

## 24. Institution, employer and government modes

Advance can be configured for:

`school | university | polytechnic | TVET | open university | employer | enterprise | professional body | ministry | regulator | national programme | NGO | community`

Institutional and government deployments inherit InstituteGPT semantics rather than creating competing education ontologies.

## 25. Work and advancement connection

Learning evidence can feed the universal Opportunities layer for:

`job, internship, apprenticeship, scholarship, fellowship, project, contract, research, entrepreneurship and promotion`

Advance does not make the employment decision. It supplies learning, competency and evidence context.

## 26. Research and teaching

Advance can connect Notebook, research and teaching capabilities for:

`research methods, literature discovery, project planning, laboratory notebooks, evidence capture, teaching design, curriculum creation, peer review and scholarly practice`.

Notebook remains the dedicated workspace; Advance owns learning progression semantics.

## 27. OpenEd relationship

`OpenEd Bot = InstituteGPT + open/distance/flexible education composition`

OpenEd Bot may use Advance learning paths, skills and credential capabilities. A named institution is configured through OpenEd rather than forked into a new education architecture.

## 28. Exams relationship

`Exams = formal examination/testing product`

Advance prepares learners for Exams and consumes results as evidence. Exams retains examination orchestration and formal test semantics.

## 29. Notebook relationship

`Notebook = study/research/teaching/evidence workspace`

Notebook records can attach to Advance learning experiences, skills, projects, evidence, assessments and credentials.

## 30. Standards and interoperability

Advance should provide adapters for:

`Open Badges, CLR, W3C VC, QTI, CASE, LTI, OneRoster, Edu-API, Caliper, UNESCO OER references, ESCO and applicable national/regional qualification and professional frameworks`.

No adapter replaces OMNII primitives.

## 31. Access and inclusion

Advance supports:

`urban | rural | low-bandwidth | offline | mobile | shared device | basic phone/voice | multilingual | disability-accessible | displaced/refugee | working adult | caregiver | non-traditional learner`

Localization is a configuration dimension.

## 32. Quality

Learning quality follows:

`design → review → delivery → evidence → learner feedback → outcome → progression → graduate/work outcome → tracer evidence → improvement`.

AI-generated content and recommendations require provenance and appropriate review.

## 33. Governance

Advance must not:

- impersonate an external credential issuer or regulator;
- treat course completion as professional authorization;
- convert simulation into authoritative practice without a governed real-world event;
- expose protected learner or child records without authorization;
- make any AI/cloud/LMS/vendor constitutionally indispensable;
- turn a provider adapter into a monopoly over the education graph;
- convert an AI benchmark into a human qualification;
- silently convert childhood experimentation into a permanent employment record.

## 34. Canonical data objects

`learning_experience, course, module, lesson, programme, learning_path, skill, competency, framework_mapping, lab_definition, practice, project, evidence, portfolio, achievement, badge, certificate, credential_reference, learning_wallet, skills_passport, cpd_activity, provider, issuer, learner, enrollment, progress, recommendation, opportunity_link`

## 35. Cross-layer flow

`HAPI identity → InstituteGPT learning intent → Advance/OpenEd/Exams/Notebook composition → learning experience/path → practice/lab/project → assessment/exam → achievement/credential reference → Skills Passport/Learning Wallet → Root verified state → Actual current state → Opportunities/Atlas projection`

Consequential transitions use IO and applicable authority/policy.

## 36. Future frontier

Advance is designed to absorb:

`adaptive curricula, AI-native teaching, continuous assessment, simulation-first training, digital twins, immersive learning, robotics learning, real-world performance credentials, continuous competency passports, human-AI co-learning, human-AI team competency, agent capability education, dynamic occupational skill graphs, automatic recognition of prior learning and continuously rebuilt lifelong pathways`.

## 37. Architectural principle

`Learning is first-class.`

`Badges/certificates/credentials are first-class outcomes of learning and advancement.`

`Labs are a major learning capability.`

`Everything else composes through the InstituteGPT education layer unless a later ecosystem boundary independently justifies a first-class product.`

`Providers and standards are adapters.`

`External authorities retain external authority.`
