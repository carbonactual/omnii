# OMNII Repository Estate Consolidation — Design

**Status:** CANONICAL DESIGN
**Date:** 2026-09-05

## Goal
Make `carbonactual/omnii` the canonical architectural and reusable-capability culmination of the Carbon Actual repository estate while preserving product specialization, provenance, source lineage, human authority boundaries, and provider independence.

## Scope
This is an architectural consolidation, not a monolithic code dump. The sweep covers first-party products, experiments, agent systems, workflow systems, data/registry systems, UI systems, and provider/framework repositories accessible through the Carbon Actual GitHub estate.

Every source artifact is classified into one of:

1. **Canonical foundation** — belongs in OMNII constitutional/runtime layers.
2. **Reusable capability** — extracted into shared packages/contracts/services.
3. **HAPI World common layer** — reusable human/AI participation, identity, learning, work, interaction, reputation, progression and world-facing experience.
4. **Domain module** — reusable domain implementation with a bounded subject model.
5. **Product composition** — remains a distinct product but consumes OMNII + HAPI World contracts.
6. **Integration adapter** — provider/vendor/protocol-specific implementation.
7. **Presentation/design asset** — UI, interaction, motion, visual, content, or design genealogy.
8. **Reference/provenance artifact** — preserved for lineage, comparison, research, or audit.
9. **Reject/supersede** — contradiction, duplicate, unsafe authority elevation, provider lock-in, or weaker formulation superseded by a stronger canonical formulation.

## Canonical relationship
`OMNII Constitutional Substrate → Common Capabilities → HAPI World Participation Environment → Domain/Product Compositions → Institutional Configuration → Integrations/Presentations`

HAPI World is therefore a common denominator for human/AI participation and product interoperability, while OMNII remains the constitutional substrate and canonical state/runtime boundary.

## Consolidation rules

- Reuse before invention.
- Preserve source provenance for every harvested artifact.
- Do not copy provider frameworks wholesale into canonical architecture.
- Do not let product-specific code redefine constitutional semantics.
- `CAPABILITY != AUTHORITY`.
- `INTELLIGENCE != AUTHORITY`.
- `ABBA != AUTHORITY ISSUER`.
- `MATCH != AUTHORIZATION`.
- `PLAN != EXECUTION`.
- `EVIDENCE != AUTHORITY`.
- `TOKENIZATION != PROOF OF OWNERSHIP`.
- `ATLAS != OPERATIONAL SOURCE OF TRUTH`.
- HAPI World does not replace OMNII; it is a shared participation/environment layer above the substrate.
- Local product state may remain as projection/cache, but canonical operational state must have a governed OMNII route.
- Original repositories remain valid source branches/reference implementations unless a deliberate retirement is justified and documented.

## Harvest priorities

### First-party intelligence and runtime
- Carbon Actual architecture/agents/API/runtime: extract stronger constitutional language, durable memory conventions, request routing, consent gates, source provenance and ecosystem services.
- ABBA + ABBA MAS: extract orchestration, planning, multi-agent coordination, authority boundaries, intelligence exchange, token/value logic, HAPI doctrine and economic formulas. Reconcile weaker or contradictory formulations against the current OMNII constitution.
- OMNI/BUNK: extract operational UI/runtime patterns and bind local state to canonical OMNII runtime.

### HAPI World
- HAPI World + Nexus + HAPI documents in ABBA/ABBA MAS become the common participation model for human/AI identity, entry, interaction, learning, skills, work, progression, world context, relationships and outward representation.
- HAPI identity remains shared across products; products must not mint duplicate human identity semantics.
- HAPI World is an environment/common denominator, not a sovereign authority layer.

### Product implementations
- NASC: forms, registries, process definitions, workflows, agents, automations, workers, institution configuration.
- RITES/NGIN/NAIRE: identity, continuity, relationship, consent, life/organization continuity and operating-environment composition.
- NOUN Student Bot: institutional-source registry, student support, escalation, bounded advisory behavior.
- Nigerian Cultural Atlas: Atlas, provenance, cultural knowledge, relationships and curated representation.
- Direct Bank App/HAPI Bank/Nano Bank/Open Bank/PabloPay/Capital: transaction, authorization, settlement, ledger, value and evidence contracts.
- Open Ballot: simulation/training mechanics and audit/evidence patterns; retain explicit non-official-election boundary.
- Charter/transport: fleet, movement, credentials/certification, routes, logistics, asset state and tokenization readiness.
- Media/Spotist/TIP/etc.: media, discovery, market, opportunity, rights, royalties, subscriptions, offers, matching and tokenized value patterns.

### Agent/workflow/tooling estate
- agent-skills: turn DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP and debugging/security/observability patterns into OMNII build governance capabilities.
- eve: preserve filesystem-first durable-agent conventions as an optional adapter pattern, not a constitutional dependency.
- caveman: preserve context-compression/session/subagent coordination patterns as agent tooling capabilities.
- workflow/command-code/claude-code-action/thunderbolt/etc.: extract workflow/execution/CI/CD/command patterns only where they strengthen the common runtime.
- universal-mcp/mcp-remote: adapters at the interoperability boundary.
- OpenClaw/CrewAI/PraisonAI/Botpress/etc.: provider/framework capability references; do not absorb upstream bulk as canonical product code.

## Data principle
“Every data should be brought” means every valuable source datum must be either:
- migrated into canonical OMNII/HAPI World data structures,
- preserved as a versioned source artifact with provenance and a declared mapping,
- or explicitly rejected/superseded with a recorded reason.

No silent loss, no silent overwrite, no unproven promotion to canonical truth.

## Architectural strengthening
The consolidation should identify repeated concepts and merge their best formulations into singular reusable contracts, especially:
- identity/#/HAPI/minted-AI lineage;
- relationship and interaction;
- intent/capability/discovery/matching/context/availability;
- authority/authorization/SEAL/delegation;
- workflow/task/process/worker/automation;
- memory/knowledge/evidence/provenance;
- value/PULSE/economic vectors/tokenization/ledger/settlement;
- forms/registries/institutional configuration;
- movement/transport/fleet/logistics;
- media/content/rights/royalties;
- agent lifecycle/planning/coordination/evaluation;
- Atlas/Root/Actual/Becoming and ecological/habitat representation;
- observability/audit/risk/security/recovery;
- API/MCP/connector/provider adapters.

## Contradiction policy
When two source artifacts conflict, prefer the formulation that:
1. preserves constitutional boundaries;
2. keeps human/legal authority explicit;
3. improves interoperability and reuse;
4. preserves provenance and reversibility;
5. avoids vendor/provider lock-in;
6. survives broader domain composition.

A conflict is not hidden: record the source pair, selected formulation, rationale, and affected consumers.

## Acceptance criteria
- Every accessible repository is represented in a consolidation manifest.
- Every significant source artifact has a disposition and provenance record.
- Shared capabilities are represented once in reusable OMNII/HAPI World contracts rather than duplicated across products.
- Product-specific implementation remains specialized and references canonical capabilities.
- Contradictory semantics are documented and resolved in favor of stronger canonical foundations.
- HAPI World is explicitly integrated as the common participation/environment layer.
- Provider frameworks remain adapters/references rather than constitutional dependencies.
- Source lineage remains queryable after consolidation.
- Consolidation is testable through automated conformance/lint checks.
