# Common Layer — Canonical Fabric Design

**Status:** CANONICAL HARDENING DESIGN — 2026-09-05

## Goal
Elevate the recurring ecosystem denominators into a reusable Common Layer without creating parallel constitutional kernels or product-specific semantic systems.

## Decision
The Common Layer is a **reusable semantic fabric** over the existing OMNII constitutional kernels and universal graph. It provides shared contracts and registries for identity, relationship, intent, capability, discovery, matching, context, availability, lifecycle, trust, authority, resource/property, value, exchange, I/O, settlement, management, communication, documents/evidence, workflow, location/time, compliance/risk, analytics/learning and interoperability.

It is not a second Constitution, second graph, second ledger, or second authority system.

## Canonical interaction
`ENTITY/IDENTITY + RELATIONSHIP + INTENT + CAPABILITY + CONTEXT + AVAILABILITY → DISCOVERY → MATCH → AUTHORITY/AUTHORIZATION → ACTION/EXECUTION → OUTCOME/EVIDENCE → SETTLEMENT/LEDGER → PULSE/LEARNING`

## Binding rules
1. Existing canonical tables remain the source of truth where their semantics already exist.
2. The Common Primitive Registry maps shared concepts to canonical backing contracts; it does not duplicate them.
3. Intent/capability matching is a reusable interaction record, not an authority grant.
4. A match never authorizes an action. Consequential execution still requires the existing authority/capability/policy gates.
5. Discovery may expose only data permitted by the applicable visibility and access rules.
6. Unknown/alien entities remain provisionally classified and cannot gain inferred trust, consent or authority.
7. Products including BUNK, I/O, Value System, Management and future products consume the fabric; they do not redefine it.
8. External standards/protocols are integration adapters, not constitutional dependencies.

## Security boundary
ABBA and agents may interpret, discover, match, plan and propose. They do not mint authority. Authority remains an explicit governed object, and SEAL remains the human/legal approval boundary where required.

## Compatibility
The fabric is transport-neutral and may be exposed through REST/API, MCP, A2A, webhooks, queues, files, events or future protocols through adapters. This is consistent with current interoperable agentic-commerce architecture, which separates capability discovery and typed commerce capabilities from authorization and settlement.
