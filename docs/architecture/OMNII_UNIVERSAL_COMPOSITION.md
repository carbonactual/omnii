# OMNII Universal Composition

**Status: CANONICAL — ecosystem composition strengthening**

## Purpose

OMNII must represent new real-world situations without creating a new constitutional primitive for every domain. Universal composition therefore provides reusable structures for situations, schemas, time, workflows, rules, decisions, cases, evidence, resources, capacity, availability, commitments, reporting, simulation, localization and exceptions.

These are composition services/contracts built on the canonical OMNII object, relationship, authority, governance, event, state, capability, resource, value, continuity and integration semantics. They do not expand or replace the foundational kernel sequence.

## Conformance rule

A new domain, product, institution, ceremony, event, service or ecosystem SHOULD first be expressed by composing existing canonical objects and capabilities.

Only when a genuine constitutional semantic is missing may the universal substrate be amended. Discovery of a new use case alone is not evidence for a new kernel.

## Universal Situation

A Situation is a governed composition representing a real-world context or circumstance.

Conceptual envelope:

`context + participants + intent + conditions + time + place + roles + rules + resources + workflow + authority + state + evidence + outcomes`

Situations may be planned, recurring, spontaneous, conditional, exceptional or emergent.

Examples include ceremonies, festivals, journeys, visits, incidents, emergencies, markets, meetings, inspections, family gatherings and operational activities.

## Schema and Form System

Schemas define structured information requirements; forms are governed interfaces for collecting or presenting data against schemas.

Typical lifecycle:

`schema → form → submission → validation → authority/policy → workflow → decision → record → evidence`

Forms MUST support versioning, provenance, localization, validation, conditional fields, attachments, consent where required, accessibility, lifecycle and auditability.

The same mechanism supports registration, permits, invitations, applications, declarations, attendance, inspections, accommodation, rider/animal records, vendor records, incidents, approvals, reports and certificates.

## Time and Calendar

The universal temporal model supports:

- exact timestamps;
- intervals and durations;
- recurring schedules;
- deadlines and lead times;
- temporal dependencies;
- availability windows;
- blackout periods;
- seasonal cycles;
- localized/traditional calendars;
- religious calendars where a domain lawfully requires them;
- relative temporal rules such as before, after, during and until.

Calendar interpretation MUST preserve source, timezone, locale and authority where relevant.

## Workflow

A Workflow is a governed ordered or conditional process toward an outcome.

A reusable workflow contract includes:

`trigger → conditions → actors → authority → tasks → dependencies → approvals → exceptions → escalation → completion → evidence → report`

Workflows MAY contain alternative, failure, emergency, timeout, retry, delegation and human-override paths.

A workflow does not itself grant authority. Each consequential execution remains subject to identity, authority, policy, capability, resource and audit controls.

## Policy and Rules

Policy/Rule objects express domain-specific constraints and decisions without becoming constitutional primitives.

Rules MAY govern eligibility, sequence, access, timing, safety, protocol, resource usage, approval, routing or escalation.

Rules MUST carry provenance, authority context, lifecycle/version and effective temporal scope where applicable.

## Decision

A Decision records an authorized determination or disposition.

A decision SHOULD identify:

`issue/intention + decision-maker + authority + rules applied + evidence considered + decision + effective time + conditions + review/appeal path + provenance`

Decision does not mean execution occurred.

## Case

A Case represents an issue requiring managed resolution over time.

Conceptual lifecycle:

`opened → classified → assigned → evidence gathered → reviewed → decided → fulfilled/resolved → reviewed/closed`

Cases support complaints, conflicts, incidents, missing-person matters, vendor disputes, operational exceptions, investigations and other matters that require accountability beyond a single event.

## Evidence and Proof

Evidence associates claims, observations or decisions with attributable support.

Conceptual chain:

`claim/observation → evidence → source → verifier → timestamp → authority/context → confidence/status`

Evidence MUST preserve provenance and MUST NOT be treated as authority merely because it exists.

## Resource Planning

Resources represent capacity or material required by an operation, while ownership/custody remains distinct.

Universal resource planning supports:

`resource → requirement → availability → reservation → allocation → utilization → release/return → condition → maintenance`

Examples include people, vehicles, horses, venues, rooms, equipment, supplies, communication capacity and emergency resources.

## Capacity

Capacity models the usable amount of a resource, service or location over a defined context and time.

Examples:

- accommodation capacity;
- venue occupancy;
- vehicle capacity;
- staffing coverage;
- animal transport capacity;
- production capacity;
- medical response capacity.

Capacity SHOULD expose available, allocated, utilized, reserved and remaining quantities where meaningful.

## Availability and Reservation

Availability expresses when and under which constraints a resource/service may be used.

Reservation is a governed commitment of availability for a defined requester, purpose, quantity and time window.

Reservation MUST remain distinguishable from ownership, custody and execution.

## Commitment and Obligation

A Commitment records a promised future contribution or action.

An Obligation represents a binding requirement arising from authority, policy, contract, transaction, relationship or other governed source.

Conceptual lifecycle:

`declared → accepted → scheduled → fulfilled → evidenced → discharged`

Exceptions, breach, renegotiation and review MUST remain attributable.

## Reporting

Reports are governed views/summaries derived from canonical records rather than alternate systems of record.

Reporting SHOULD support:

- readiness;
- attendance/participation;
- operations;
- safety and incidents;
- health/medical;
- mobility/traffic;
- accommodation/hospitality;
- economics/value;
- sponsors/partnerships;
- youth/workforce;
- compliance;
- after-action review;
- lessons learned;
- next-cycle recommendations.

Reports MUST preserve source scope, time range, methodology/version and provenance.

## Simulation and Planning

Simulation composes existing objects, states, constraints and policies to estimate possible outcomes without confusing prediction with observed fact or authorization.

Simulation MAY evaluate:

- demand spikes;
- route closures;
- resource shortages;
- additional visitors;
- weather scenarios;
- staffing changes;
- capacity overload;
- alternative schedules.

Predictions and simulated states MUST remain distinguishable from actual evidence.

## Localization and Variation

A composition may inherit universal semantics while supplying local configuration for:

- language;
- terminology;
- protocol;
- calendar;
- authority;
- jurisdiction;
- cultural practice;
- workflow;
- forms;
- rules;
- resources;
- reporting.

Local configuration MUST NOT silently redefine universal constitutional semantics.

## Exception and Unknown Handling

OMNII MUST support a first-class path when a situation does not match an existing composition.

Conceptual route:

`detect → classify → contextualize → obtain required authority → compose temporary handling → execute → record → review → learn → optionally promote pattern`

An unknown situation is therefore not automatically an architectural failure. It becomes an evidence-bearing composition candidate subject to governance.

## Conformance Matrix

Any ecosystem/product deployment SHOULD be able to map each real-world concern to one or more universal structures:

| Real-world need | Universal composition |
|---|---|
| New event/situation | Situation |
| Data collection | Schema/Form |
| Date/period/deadline | Time/Calendar |
| Process | Workflow |
| Rule/etiquette/eligibility | Policy/Rule |
| Authorized determination | Decision |
| Dispute/problem/investigation | Case |
| Claim/verification | Evidence/Proof |
| Equipment/people/venue | Resource |
| Hosting/occupancy/service limits | Capacity |
| Rent/book/hold | Availability/Reservation |
| Promise/duty | Commitment/Obligation |
| Management summary | Report |
| What-if planning | Simulation |
| Local tradition/rules | Localization |
| Unanticipated circumstance | Exception/Unknown handling |

## Non-negotiable boundaries

These composition services do not redefine:

- Being;
- Identity;
- the canonical object envelope;
- universal relationships;
- authority;
- constitutional governance;
- the foundational kernel sequence;
- human consent requirements;
- ABBA's non-sovereign role.

Products such as Emirati MUST consume these capabilities rather than create competing foundations.
