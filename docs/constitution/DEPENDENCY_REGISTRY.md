# DEPENDENCY REGISTRY

The Dependency Registry is the canonical map of constitutional dependencies across kernels, objects, products, agents, services, and institutions.

## Purpose
Prevent hidden coupling, circular constitutional dependencies, and uncontrolled architectural drift.

## Dependency Properties
- Dependency ID
- Source
- Target
- Dependency type
- Required or optional status
- Version or compatibility constraint
- Authority
- Lifecycle
- Rationale

## Constitutional Rule
Dependencies flow toward more foundational layers. Foundational kernels must not become dependent on product-specific implementations.

## Core Direction
BEING → IDENTITY → KNOWLEDGE → MOTION → VALUE → TRUST → RELATIONSHIP → INTENT → EXECUTION → CAPABILITY → RESOURCE → COMPOSITION → CONTINUITY → INTEGRATION

Governance and orchestration govern authorized use across the stack rather than replacing the foundational sequence.
