# Carbon Actual Architecture Freeze v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze a compressed, reusable Carbon Actual architecture that defines the universal capability ontology, economic ontology, product-composition blueprint, and governance rules for future ecosystem branches.

**Architecture:** Preserve Carbon Actual as the ecosystem and treat Omni as an operating state/property of movement and orchestration rather than the ecosystem name. Compress the constitutional model into stable families while keeping Being, ABBA, Value, Pulse, IO, Union, Communication, Continuum, Curation, Governance, Mathematics, Integration, HASH, SEAL, Terminal, Root, Index, Vault, Actual, Atlas, Becoming, Ash, Phoenix, HAPI and HAPI World as defined constitutional/capability concepts. All downstream products are compositions of reusable capabilities and may extend the ontology without breaking the core.

**Tech Stack:** Markdown constitutional specifications in GitHub; repository-native documentation; no application-code changes in this freeze.

## Global Constraints

- Carbon Actual is the ecosystem name; Omni is an operating state/property, not the ecosystem name.
- The architecture must remain compressed, composable, extensible and domain-neutral.
- Integration is a core value and open/replaceable interfaces are preferred.
- Physical, digital, human and machine capabilities are first-class.
- Humans and intelligence are designed for balanced, enabled, optimized coexistence; automation must not automatically replace meaningful human activity.
- Privacy, provenance, authority, security and user control are mandatory architectural concerns.
- No guarantee of being literally unbreakable or stronger than quantum computing; security is designed for resilience, compartmentalization and post-quantum migration.
- Tokenization, fractionalization, decimalization, democratization and decentralization are supported as mechanisms, not mandatory implementations for every object.
- Ash represents recoverable residual value/security residue; Phoenix is an active defensive response.
- Products, services, contracts, partnerships, hardware and human services are all compositions of the same capability fabric.
