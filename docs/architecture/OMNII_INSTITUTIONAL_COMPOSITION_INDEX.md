## Cross-system traceability

Every consequential action should resolve to:

`actor → authority → intent → policy → workflow/case → task → execution → resulting state → event → evidence → audit`

Where value is involved:

`execution → obligation → invoice/claim → authorization → payment/settlement → reconciliation → ledger → audit`

## Gap/conformance controls

The institutional fabric detects and routes orphan records, duplicate identities, duplicate submissions, skipped workflow steps, expired authority, unauthorized approvals, unowned digital assets, unexplained deployments, payment mismatches, stale commitments, missing evidence, unresolved vulnerabilities, failed backups and incomplete handoffs into governed cases rather than silently overwriting or discarding them.

## Conformance rule

Before implementing an institution-specific requirement:

1. Search the universal registry/capability shelf.
2. Reuse an existing capability if semantically sufficient.
3. Configure forms, workflows, policies and UI before writing bespoke logic.
4. Extract recurring patterns into reusable modules.
5. Keep local law, institutional authority, data and policy at the configuration/domain boundary.
6. Version every deployable shared component.
7. Produce an explicit handoff/exit package.

## Strategic rule

Every reference deployment should leave OMNII stronger than it found it. A successful institutional implementation is both a customer solution and a source of validated reusable capability.
