# TIP Capability, Infrastructure & Agent Markets

**Ecosystem:** Carbon Actual / OMNII  
**Product:** TIP — Trade, Investment & Value Markets  
**Status:** CANONICAL EXTENSION — approved  
**Purpose:** Extend TIP from asset/market trading into capabilities, infrastructure, recurring economic relationships, and machine-accessible/agentic markets.

---

## 1. Core Principle

> **Anything that can be legitimately owned, controlled, supplied, consumed, licensed, reserved, financed, subscribed to, exchanged, contracted, measured, invested in, or deployed as productive capacity may be represented as a TIP Market Object or Capability.**

The ontology must distinguish the underlying thing/capability from the commercial mechanism used to access it.

Therefore TIP supports both:

```text
THING / ASSET / RESOURCE
CAPABILITY / SERVICE / CAPACITY
RIGHT / CLAIM / LICENSE
CONTRACT / SUBSCRIPTION
INFRASTRUCTURE
FLOW / USAGE
OPPORTUNITY
OUTCOME
```

No object is automatically tradable, investable, financeable or tokenizable merely because it is represented in TIP. Eligibility, law, authority, verification, market rules and risk controls remain separate.

## 4. API / MCP / CLI as Market Access

TIP must treat technical interfaces as first-class **access capabilities**.

### API

An API can expose:

- market data
- quotes
- orders
- portfolios
- valuations
- finance applications
- services
- inventories
- logistics
- payments
- reporting
- settlement
- agent tools

API access can itself be:

- free
- metered
- subscription-based
- tiered
- enterprise-licensed
- usage-priced
- capacity-reserved
- outcome-priced where contractually appropriate.

### MCP

MCP is an integration/access layer through which compatible AI applications can discover and call authorized tools, data and business logic. TIP should expose MCP capabilities for eligible market and commerce functions and consume external MCP tools under strict authentication, authorization and sandboxing.

MCP must never become an implicit authority channel. Tool invocation remains subordinate to TIP identity, consent, permissions, policy and risk controls.

### CLI

CLI access is a first-class operator/automation interface for:

- research
- market scans
- portfolio inspection
- backtests
- simulations
- order preparation
- deployment
- administration
- reconciliation
- monitoring
- infrastructure operations

CLI actions must map to the same underlying APIs/policies as GUI, prompt, agent and scheduled actions.

Privacy, intellectual-property rights, confidentiality, trade secrets and data-protection obligations remain intact.

```text

   ↓

   ↓

   ↓

   ↓
CAPACITY
   ↓
USAGE / REVENUE
   ↓
MAINTENANCE
   ↓
UPGRADE / REPOWER
   ↓
REUSE / RETIRE / RECOVER
```

### Data centres

A data centre may contain many market objects:

- land
- building
- power connection
- solar/renewable generation
- batteries
- cooling systems
- generators
- transformers
- networking
- racks
- servers
- GPUs/accelerators
- storage
- software
- security
- fibre connectivity
- water/cooling capacity
- compute capacity
- contracted capacity
- tenant contracts
- carbon/environmental attributes

TIP must therefore be able to finance, value, lease, operate, insure and trade individual components or the integrated project where legally appropriate.

Current market evidence reinforces this design: Knight Frank forecasts global data-centre capacity to rise from 62 GW in 2025 to more than 110 GW by 2028, with $1.4–$1.6 trillion of investment required for the associated build-out. citeturn983416search5

Data-centre demand also creates a direct intersection between real estate, compute, power, financing and grid capacity. Recent reporting shows regulators are already addressing speculative data-centre power demand, illustrating why TIP should model both physical capacity and contracted/project-backed demand rather than only financial price. citeturn983416news38

## 20. Canonical Rule

> **TIP trades more than things. It coordinates access to value-producing things, rights, capabilities, capacity, services, infrastructure, knowledge, intelligence and economic relationships.**

API, MCP, CLI, Prompt Trading, agents, AI crews and human interfaces are therefore not separate economic universes. They are access and execution surfaces over the same TIP Market Object, Capability, Contract, Value, Risk and Settlement architecture.

The architecture must remain open to future interfaces and market forms without requiring another foundational redesign.
