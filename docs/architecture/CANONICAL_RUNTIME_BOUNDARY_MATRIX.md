# Canonical Runtime Boundary Matrix

| Concern | Canonical home | Must not become | Boundary rule |
|---|---|---|---|
| Constitutional law | Constitution/frozen docs | Product policy | Products inherit; amendments explicit |
| Identity | HASH/identity contracts | Capability registry | Identity ≠ capability |
| Authority | SEAL/policy/delegation | Matching/interpretation | Authority evaluated separately |
| Objects | Universal object model | Product-specific universe | Branches extend, do not fork |
| Events/evidence | Event/evidence contracts | Current-state cache | State remains rebuildable where practical |
| Capability | Common Layer | Provider implementation | Interface before vendor |
| Intelligence | ABBA/HAPI World | Universal authority | Intelligence operates within authority |
| Human execution | HAPI | Agent identity | Human capability remains first-class |
| Workflow | Composition/runtime | Constitution | Workflows consume canonical capabilities |
| IO | Flow/exchange semantics | Value currency | IO ≠ Value |
| Pulse | Feedback/evidence | Currency/permission | Pulse ≠ automatic Value |
| Value | Economic ontology | Surveillance metric | Purposeful, consent-aware measurement |
| Ledgers | Logical ledger model | Single blockchain | Ledger implementation remains agnostic |
| Root/Index/Vault/Actual/Atlas | Projection/access roles | Competing truths | Projections never silently become canonical source |
| Ash | Residual/security classification | Hidden deletion | Residuals remain traceable/recoverable where appropriate |
| Phoenix | Security/recovery response | General orchestration | Governed response only |
| Products | Domain composition | Constitutional layer | Compose shared capabilities |
| Providers | Adapters | Canonical semantics | Replaceable implementations |
