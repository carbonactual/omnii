# OMNII Institutional Registry Atlas

**Status: CANONICAL REUSABLE REGISTRY CATALOG**

## Purpose

The Institutional Registry Atlas defines reusable logical registry families for government, regulators, agencies, companies, schools, universities, clubs, associations, NGOs, research institutions, security organizations and other governed institutions.

The Atlas does **not** create a second constitutional registry ontology. The constitutional baseline remains the 28 universal registries. Atlas entries are logical registries, projections, domain registries or views that resolve to one or more canonical registries.

## Registry contract

Every registry should preserve, where applicable:

`stable_id + type + version + lifecycle + authority + provenance + ownership/custody + relationships + permissions + evidence + events + audit + retention + reconciliation + continuity`

A registry is a source-of-truth boundary only when explicitly designated. Otherwise it is a projection or index over authoritative objects.

## Universal lifecycle

`discover → register → validate → verify → approve → activate → update → suspend → renew → transfer → retire → archive`

## Anti-gap rules

Every institutional deployment must be able to answer:

`Who is involved? What exists? Who has authority? What was requested? What evidence exists? What work is pending? Who must act? By when? What automation is allowed? What happened? What changed? What did it cost? What value/outcome resulted? Was it reconciled? Was it compliant? What remains unresolved? Who can take over?`

Registries should expose gap detection for missing owners, missing authority, missing evidence, expired credentials, orphaned records, stale cases, breached SLAs, unmatched financial records, duplicate identities, inconsistent master data, unauthorized changes, failed integrations, broken dependencies, unclosed incidents and incomplete handoffs.

## Composition rule

`Registry → Form → Submission → Case → Workflow → Task → Rule/Automation → Execution → Event/Log → Evidence → Decision → Reconciliation → Finance/Settlement → Audit/Compliance → Pulse/Value → Continuity`

The registry layer is the addressability fabric; it does not itself grant authority.
