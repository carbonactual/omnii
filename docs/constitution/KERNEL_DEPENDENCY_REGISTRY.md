# KERNEL DEPENDENCY REGISTRY

## Purpose
Canonical dependency ordering for constitutional kernels and cross-cutting constitutional layers.

## Foundational Sequence
1. BEING
2. IDENTITY
3. KNOWLEDGE
4. MOTION
5. VALUE
6. TRUST
7. RELATIONSHIP
8. INTENT
9. EXECUTION
10. CAPABILITY
11. RESOURCE
12. COMPOSITION
13. CONTINUITY
14. INTEGRATION

## Dependency Rules
- Foundational kernels must not depend on product implementations.
- A kernel may reference a higher kernel semantically only where the reference does not create implementation coupling.
- Cross-cutting authority must remain explicit.
- Circular dependencies require constitutional review rather than silent accommodation.

## Cross-Cutting Dependencies
GOVERNANCE constrains authority across the sequence.
ORCHESTRATION/ABBA coordinates authorized use of the sequence.
ECONOMIC CONSTITUTION governs economic/value mechanisms.
AGENT CONSTITUTION governs agent participation and authority.

## Registry Record
Each future machine-readable dependency entry should contain: source kernel, target kernel, dependency type, mandatory/optional status, rationale, authority, lifecycle, compatibility constraint, and provenance.
