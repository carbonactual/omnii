# OMNII Canonical Terminology

**Status: CANONICAL.** When another repository document conflicts with this glossary, this glossary governs unless a later constitutional amendment explicitly supersedes it.

| Term | Canonical meaning | Boundary |
|---|---|---|
| Being | The fact/state of existence or participation represented in OMNII. | Foundational; not a product or agent. |
| Identity | The stable identity reference by which a subject/object is attributable. | Identity is not authority. |
| Object | Any identifiable, typed, governed participant represented by the universal object envelope. | Entity/domain names are object specializations. |
| Entity | A domain-level object treated as a distinct participant. | Not a competing primitive to Object. |
| Knowledge | Evidence, information or structured understanding attributable to sources and context. | Knowledge is not memory. |
| Memory | Persisted knowledge/experience retained for later use under lifecycle and authority rules. | Implementation/domain concern built on Knowledge. |
| Motion | Change, movement or transformation across state/time. | Does not mean an event log. |
| Event | An immutable/append-aware record that something occurred or was observed. | Does not itself authorize or execute. |
| State | The current modeled condition of an object/system at a point in time. | State is not an event. |
| Intent | A declared desired outcome or direction. | Does not imply authorization. |
| Action | A requested operation or operation description. | Does not imply execution occurred. |
| Execution | The governed attempt/act of performing an action. | Attribution and outcome are required. |
| Capability | A defined ability to perform a class of operation. | Capability never implies authority. |
| Authority | The scoped, attributable, revocable right/mandate to act. | Distinct from capability and intelligence. |
| Permission | A concrete allowed operation derived from authority, policy and constraints. | Permission is narrower than authority. |
| Resource | Capacity or material required/controlled by an operation. | Resource is not value or ownership. |
| Value | A modeled measure of contribution, consequence, utility or economic position. | Not synonymous with money. |
| Asset | A resource/right/position recognized as having positive economic or operational value. | Asset is a value-domain object. |
| Relationship | A typed, addressable connection between source and target with semantics and governance. | Not a generic link. |
| Dependency | A relation in which one component requires another for defined correctness. | Not equivalent to relationship in general. |
| Composition | The governed assembly of canonical objects/capabilities into a higher-order system. | Products compose; they do not redefine primitives. |
| Workflow | An ordered/conditional set of actions/executions governed toward an outcome. | Workflow is not a single execution. |
| Transaction | A governed atomic/business/economic exchange or stateful commitment with auditability. | Transaction is not every event. |
| Agent | An autonomous or semi-autonomous execution participant operating under a contract and delegated authority. | Agent is not foundational. |
| ABBA | OMNII's master intelligence/orchestration layer. | Not sovereign; not a constitutional prerequisite. |
| Governance | The authority, policy, rule, decision and accountability system that constrains action. | Cross-cutting. |
| Trust | A modeled degree/basis of confidence, assurance or relationship condition. | Not identity or authority. |
| Continuity | Preservation and controlled progression of identity, state, knowledge, relationships and obligations across time. | Cross-domain lifecycle concern. |
| Integration | Governed connection across system boundaries. | Cross-cutting kernel. |
| Ecosystem | A bounded composition of people, organizations, products, services, resources and governance operating on shared substrate. | Higher-order composition. |
| Product | A bounded user/business composition delivering a defined outcome. | Never a constitutional primitive. |
| Service | A capability exposed for use by authorized consumers. | Implementation/runtime composition. |
| Territory | A bounded physical/geographic/jurisdictional domain represented as governed objects and relationships. | Not inherently a legal sovereignty claim. |
| World | A large bounded modeled/operational domain containing objects, relationships and systems. | Future/higher-order composition. |

## Semantic separation rules

1. Capability ≠ authority.
2. Intelligence ≠ authority.
3. Orchestration ≠ ownership.
4. Planning ≠ execution.
5. Event ≠ state.
6. Command/action ≠ execution.
7. Query ≠ mutation.
8. Relationship ≠ dependency.
9. Value ≠ money.
10. Resource ≠ asset.
11. Product ≠ constitutional primitive.
12. Agent ≠ constitutional kernel.
13. Ecosystem/world models extend the object graph; they do not replace it.
