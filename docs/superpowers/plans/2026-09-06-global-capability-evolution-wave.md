# Global Capability Evolution Wave Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the OMNII ecosystem with the next eight reusable global capability layers after Sourcing, Opportunity, Matching/Discovery, Market Intelligence, Research Intelligence and Verification/Trust.

**Architecture:** Add one canonical scope document per capability, then register the capabilities in the shared economic coordination register and culmination index. Each capability is global-by-default, jurisdiction-aware, provider-independent, evidence-aware, and must consume existing OMNII/TIP/IO/Value/Pulse boundaries instead of creating duplicate ontologies.

**Tech Stack:** Markdown canonical architecture documents, GitHub repository contents API, existing OMNII canonical documentation.

**Spec:** `docs/canonical/OMNII_GLOBAL_CAPABILITY_EVOLUTION_ROADMAP.md`

## Global Constraints

- Every new capability is **global-by-default**.
- Geography is context, jurisdiction, availability and constraint, not a separate ontology.
- Products compose shared capabilities; they do not redefine them.
- External services are adapters/evidence sources, not constitutional authority.
- Human Authority, evidence, policy, TIP/IO, Value/VCE and Pulse boundaries remain intact.
- Unknown, unverified, stale and inferred states must remain explicit.
- Regulated execution remains with the appropriate authority/provider.
- Existing canonical capabilities must be strengthened before creating overlapping new ones.
