# BUNK — OMNII Ecosystem Composition Contract

**Status:** CANONICAL
**Product:** `BUNK`
**Ecosystem:** `OMNII`
**Economic foundation tool:** `TIP`

## Canonical rule

BUNK is a **product composition of the OMNII ecosystem**. It is not an independent platform architecture, foundation subsystem, universal runtime, or alternate economic system.

```text
OMNII ecosystem
  ├─ universal constitutional/runtime substrate
  ├─ shared identity / authority / graph / registry / evidence / persistence
  ├─ ABBA / agents / workflows / events / Pulse / reconciliation
  ├─ foundation tools, including TIP
  └─ products, including BUNK
```

BUNK consumes the ecosystem; the ecosystem does not become dependent on BUNK semantics.

## Ownership of semantics

| Concern | Canonical owner | BUNK behavior |
|---|---|---|
| Identity | OMNII | Consume one identity model |
| Authority / SEAL | OMNII | Request/evaluate/consume authority; never mint it |
| Objects / graph | OMNII | Compose property-domain views over canonical objects |
| Evidence / provenance | OMNII | Attach property evidence and preserve lineage |
| Registries | OMNII | Materialize property-specific registry views where governed |
| Persistence / Vault / Atlas | OMNII | Consume shared boundaries and projection rules |
| Events / ledger / Pulse | OMNII | Emit/consume property events and outcomes |
| Agents / ABBA | OMNII | Use delegated intelligence/orchestration |
| Trade / investment / finance / markets / settlement | TIP | Delegate all canonical economic semantics to TIP |
| Property product experience | BUNK | Own property discovery, workflows, operations and domain experience |

## Hard prohibitions

BUNK must not create or become the source of truth for:

- a second universal identity system;
- a second authority or SEAL issuer;
- a second universal graph;
- a second universal registry ontology;
- a second persistence/Vault boundary;
- a second canonical ledger;
- a second universal market/economic ontology;
- a TIP replacement;
- ecosystem-wide constitutional meaning.

BUNK may have implementation-specific tables, APIs, projections, caches and product contracts when they are required for the product, but they remain downstream materialization of OMNII semantics.

## Property-domain ownership

BUNK is the ecosystem's universal property product. It owns the product composition for:

- land, parcels, estates and development sites;
- buildings, units, facilities and property-linked infrastructure;
- tenure, title representations and property rights/interests;
- access, usage, temporal and spatial property interests;
- cemetery, burial, memorial and related property interests;
- natural, ecological, cultural, heritage and biological/material property candidates;
- intangible and digital property representations relevant to property workflows;
- property-linked financial interests as represented and routed through TIP;
- agents, brokers, professionals, contractors, vendors and artisans in the property value chain;
- development, construction, transaction, tenancy, operations, maintenance, redevelopment, recovery and preservation;
- historical, contemporary, emerging, futuristic, extraterrestrial and unknown property candidates.

These are **BUNK product concerns**, not replacements for the universal OMNII object model.

## Economic composition

The canonical economic path is:

```text
BUNK property context
   ↓
TIP economic intent / market / investment / finance contract
   ↓
TIP execution / clearing / collateral / settlement / reconciliation
   ↓
OMNII events / evidence / Pulse / accounting boundaries
   ↓
BUNK property outcome
```

BUNK may expose a seamless property experience, but it must not hide the semantic ownership of economic operations in TIP.

## Product composition rule

Every new BUNK capability must first be classified as one of:

1. existing OMNII shared capability;
2. existing TIP capability;
3. genuinely BUNK-specific property capability;
4. external integration/adapter;
5. prohibited duplication.

Implementation should prefer composition over invention.

## Frontier rule

BUNK may represent a newly observed, speculative, extraterrestrial or unknown object/interest without asserting that it is legally recognized property.

`UNKNOWN` is an epistemic state. It does not itself establish ownership, sovereignty, personhood, consent, authority, tradeability, investment eligibility or legal title.

## Operational rule

BUNK product routes may evolve independently in presentation and workflow, but cross-product semantics remain inherited from OMNII. A BUNK implementation must remain compatible with the ecosystem's identity, authority, graph, evidence, persistence, event, reconciliation and TIP contracts.
