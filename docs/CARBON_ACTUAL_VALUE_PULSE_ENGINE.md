# Carbon Actual Value + Pulse Engine

**Status:** Canonical design; formulas remain subject to empirical validation

## Purpose

Create a common measurement framework for the ecosystem without pretending that every consequence can be reduced to one simplistic price.

## 1. Pulse

Pulse is evidence of what happened after an action, contribution, transaction, interaction or state change.

Pulse can contain:

- outcome
- quality
- completion
- time response
- resource consumption
- human/agent effort
- physical distance
- energy
- computation
- data/bandwidth
- reliability
- risk
- maintenance impact
- social/community impact
- environmental impact
- downstream consequences
- confidence/evidence quality

Pulse is **observed feedback**, not automatically monetary value.

## 2. Value

Value is the normalized economic/operational reference used to compare contributions and consequences across contexts.

Value should be multidimensional internally and normalized only where comparison is justified.

Core dimensions may include:

```text

ENERGY
LABOR
ATTENTION
COMPUTATION
DATA
BANDWIDTH

ENVIRONMENTAL EFFECT
```

## 3. Contribution and consequence

For an activity:

```text
Contribution = measured resources sent/committed
Pulse = measured consequential return/feedback
Balance = Pulse - Contribution
```

This is a conceptual balance function, not yet a monetary formula.

The system may classify the resulting position as:

- positive return
- ecosystem responsibility/liability
- balanced/reference
- uncertain
- disputed

The ecosystem's inverted economic doctrine then determines responsibility and treatment.

## 4. Value reference

Carbon Actual requires a **Value Reference Band**, not merely one universal number.

The band should contain:

- floor: minimum sustainable operating condition
- reference/median: balanced condition
- ceiling: resource/risk boundary
- tolerance: acceptable variation
- context: location, domain, entity and time

This prevents a single token price from pretending to represent every form of value.

## 5. Measurement provenance

Every measurement should carry:

```text
source
method
unit
precision
confidence
consent basis
timestamp
context
transformation history
```

Derived values must remain distinguishable from primary observations.

## 6. Privacy-preserving measurement

Measurement is not permission for surveillance.

The engine should prefer:

- local computation
- aggregation
- minimization
- pseudonymization
- selective disclosure
- proofs/attestations
- consent
- purpose limitation
- retention limits

The system should measure what is necessary to establish a legitimate outcome, not everything merely because it can.

## 7. Value vectors

A useful internal representation is a vector rather than one scalar:

```text
V = [time, energy, labor, data, compute, material, capital,
     risk, quality, outcome, social, environmental, ...]
```

A domain-specific evaluator can transform V into a contextual score or settlement value.

This preserves information that would be lost by immediately compressing everything into money.

## 8. Asset/liability inversion

The ecosystem's economic doctrine treats responsibility differently from conventional economics.

Conceptually:

```text
If consequential value > contributed value:
    positive return / asset-side consequence

If consequential value < contributed value:
    liability-side consequence / ecosystem responsibility

If approximately equal:
    balanced Value reference
```

But asset/liability classification must also consider ownership, obligations, risk, custody, law, externalities and lifecycle. The balance equation alone is insufficient for legal or accounting classification.

## 9. No-waste accounting

Every measured contribution must end in a classified state:

```text
useful value
reusable resource
evidence/knowledge
obligation/liability
residual/waste
security context
unknown
```

Residuals become Ash context rather than disappearing from the accounting model.

## 11. Multiple ledgers

Pulse and Value may feed separate interoperable ledgers:

- event/Pulse ledger
- value ledger
- asset/liability ledger
- ownership ledger
- obligation ledger
- settlement ledger
- provenance ledger
- capability ledger
- security/audit ledger

A blockchain may anchor selected records; it is not required for every internal computation.

## 12. Mathematical validation roadmap

Before monetary policy is frozen, test the model against:

- dimensional consistency
- conservation/non-conservation of resources
- double counting
- incentives
- gaming
- adverse selection
- externalities
- inflation/deflation effects
- liquidity
- volatility
- fairness
- privacy cost
- measurement error
- uncertainty
- dispute resolution
- regulatory/accounting compatibility

## 13. Core principle

> **Pulse tells the ecosystem what happened. Value helps the ecosystem understand what it means.**

Neither should be reduced to a simplistic score merely for convenience.
