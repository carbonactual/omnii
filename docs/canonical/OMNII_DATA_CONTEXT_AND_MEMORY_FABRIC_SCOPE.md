# OMNII Data, Context & Memory Fabric — Canonical Scope

**Status:** CANONICAL CAPABILITY EXTENSION  
**Family:** Knowledge & Data / Intelligence  
**Scope:** Global  
**Purpose:** Make trusted, permissioned, portable context available to every composition, agent, product and experience without creating fragmented data silos.

## 1. Data as Ecosystem Infrastructure

The fabric covers the full lifecycle of structured and unstructured information:

```text
CAPTURE → INGEST → IDENTIFY → NORMALIZE → CLASSIFY → VALIDATE → STORE → INDEX → RETRIEVE → TRANSFORM → SHARE → UPDATE → ARCHIVE / DELETE → PROVE / RECOVER
```

It interoperates with Root, Index, Vault, Actual, Atlas and Terminal rather than replacing their constitutional roles.

## 2. Sources

Sources may include:

- human input;
- forms and registries;
- enterprise systems;
- documents and media;
- sensors and machines;
- APIs and event streams;
- public/open data;
- external providers;
- agent outputs;
- transaction and operational records;
- physical-world observations.

## 3. Context Engine

Context assembly selects only the information authorized and relevant to the active composition:

- user/participant context;
- task context;
- organizational context;
- temporal context;
- geographic/contextual context;
- relationship context;
- policy context;
- historical context;
- live state;
- evidence and provenance.

Context must be explicit about source, freshness, confidence and authorization.

## 4. Memory Classes

The ecosystem supports separated memory classes:

- working/task memory;
- conversational/session memory;
- personal/context memory;
- organizational memory;
- knowledge/reference memory;
- operational state;
- procedural memory/skills;
- event/history memory;
- safety/audit memory.

Retention, access, export and deletion follow declared authority and policy.

## 5. Data Quality

The fabric evaluates:

- completeness;
- validity;
- consistency;
- freshness;
- duplication;
- provenance;
- uncertainty;
- lineage;
- schema compatibility;
- anomaly state.

Unknowns remain unknown. Missing data is not silently fabricated.

## 6. Knowledge and Retrieval

The fabric may support:

- relational queries;
- full-text search;
- semantic retrieval;
- vector retrieval;
- graph traversal;
- structured knowledge graphs;
- temporal retrieval;
- hybrid retrieval;
- source ranking;
- evidence-aware retrieval.

Provider and storage choices remain replaceable.

## 7. Permissions and Privacy

Data access is evaluated against identity, purpose, authority, policy and scope. Sensitive information should use minimization, selective disclosure, encryption and auditable access.

## 8. Portability

Users and organizations should be able to:

- export their own authorized state;
- migrate providers;
- restore data;
- replace models;
- replace vector/search/storage providers;
- federate across jurisdictions;
- maintain provenance through movement.

This is a shared context and knowledge fabric, not a single database vendor, vector store, data warehouse or proprietary AI memory system.
