# Carbon Actual Knowledge, Memory, Evidence & Learning Architecture

**Status:** Canonical kernel contract

## Purpose

Carbon Actual needs one compressed information architecture that can serve every branch without creating isolated knowledge silos.

The architecture distinguishes data, information, knowledge, evidence, memory, learning and intelligence while allowing them to interact.

## 1. Data

Data is an observed or supplied representation of a fact, measurement, event, signal or record.

Data retains source, time, context and integrity metadata where applicable.

## 2. Information

Information is data placed into a meaningful context so that it can answer a question or describe a state.

## 3. Knowledge

Knowledge is an organized relationship between information, concepts, rules, patterns, procedures and experience that can support reasoning or action.

Knowledge may be:

- declarative
- procedural
- relational
- contextual
- experiential
- domain-specific
- derived

## 4. Evidence

Evidence is information used to support, challenge or qualify a claim.

Evidence has:

- source
- provenance
- Providence where relevant
- acquisition context
- timestamp
- integrity
- confidence/quality indicators
- applicable scope

Evidence does not automatically equal truth.

## 5. Claim

A Claim is an assertion about an object, event, relationship, capability, state or outcome.

Claims may be:

- asserted
- observed
- verified
- disputed
- inferred
- simulated
- expired
- superseded

## 6. Memory

Memory is retained information or knowledge that can influence future state, reasoning or action.

Memory is scoped rather than treated as one undifferentiated database.

Possible memory classes include:

- identity memory
- relationship memory
- episodic/event memory
- procedural memory
- organizational memory
- operational memory
- preference memory
- learning memory
- safety memory
- legal/governance memory

## 7. Memory ownership and access

Memory must retain ownership/rights, authority, privacy scope, retention policy and access rules.

A system's ability to remember something does not automatically create a right to disclose it.

## 8. Learning

Learning is a state-changing process that updates a model, capability, knowledge structure, policy recommendation or behavioral strategy from evidence and experience.

Learning must identify:

- what changed
- why it changed
- evidence used
- model/version/policy involved
- confidence
- scope of applicability
- rollback/revision path where applicable

## 9. Intelligence

Intelligence is the capacity to interpret, reason, learn, plan, decide within authority, communicate, create, coordinate and act.

Intelligence consumes and produces data, information, knowledge, memory, evidence and Pulse.

## 10. ABBA

ABBA is the ecosystem-level intelligence/orchestration layer. Product-specific intelligences may operate within HAPI World and other authorized contexts, while contributing appropriate learning and evidence back into the governed ecosystem.

The architecture must avoid creating one giant undifferentiated memory store.

## 11. HASH intelligence relationship

A HASH may have an associated intelligence environment that learns with the human subject within defined authority and privacy boundaries.

The associated intelligence can integrate authorized intelligence providers and tools without surrendering the HASH's underlying identity or rights to those providers.

## 12. Root / Index / Actual / Atlas relationship

The canonical information architecture is:

```text
ROOT
  = subject-scoped canonical/private information

INDEX
  = discoverable/general directory and routing information

ACTUAL
  = operational/current interaction and life/work state

ATLAS
  = curated public/authorized profile and capability representation
```

These are views and governance boundaries, not necessarily four unrelated physical databases.

They may be implemented using shared infrastructure while maintaining strict authorization and data boundaries.

## 13. Evidence flow

```text
SOURCE
 ↓
CAPTURE
 ↓
INTEGRITY / PROVENANCE
 ↓
CLAIM
 ↓
VERIFICATION / QUALIFICATION
 ↓
KNOWLEDGE
 ↓
CURATION
 ↓
DECISION / ACTION
 ↓
PULSE
 ↓
LEARNING
```

## 14. Provenance

Provenance records where information came from, how it changed and which transformations produced the current representation.

## 15. Providence

Providence records the source/guardian/provision context relevant to stewardship, origin, responsibility or continuity.

Provenance and Providence are related but intentionally distinct concepts.

## 16. Knowledge graph

Carbon Actual should use a universal relationship graph to connect:

- entities
- capabilities
- resources
- claims
- evidence
- events
- contracts
- relationships
- products
- organizations
- teams
- integrations
- policies
- outcomes

The graph is a connective layer, not a replacement for every specialized datastore.

## 17. Specialized storage

Products may use specialized databases, search indexes, object stores, ledgers, vector stores, graph stores or other technologies when appropriate.

The universal model governs meaning and relationships; implementation storage remains replaceable.

## 18. Learning boundary

Learning must not silently rewrite canonical history.

Historical records remain historical. New learning creates a new interpretation, model, policy or state where appropriate.

## 19. Simulation boundary

Simulated knowledge must be explicitly marked as simulated and must not be presented as observed reality.

HAPI World can therefore operate as an experimentation environment without contaminating production truth.

## 20. Certification

A participant or intelligence claiming a capability should be able to reference evidence and certification where the capability requires qualification.

Institute GPT and other authorized certification systems can contribute credential evidence to the universal model.

## 21. Knowledge lifecycle

```text
CAPTURE → VALIDATE → CLASSIFY → CONNECT → CURATE → USE → OBSERVE → LEARN → REVIEW → RETIRE/SUPERSEDE
```

## 22. Universal rule

Product branches must reuse the universal knowledge, memory, evidence and learning primitives. Domain-specific knowledge belongs in domain extensions, not duplicated foundations.
