# Emirati Composition Boundary

**Status: CANONICAL PRODUCT ARCHITECTURE**

Emirati is a Carbon Actual ecosystem composition implemented on OMNII. It does not define a competing constitutional ontology, universal graph, identity system, authority model or foundational kernel.

## Composition

`OMNII universal substrate → universal composition services → Emirati local configuration → Emirati experiences`

Local configuration may define legitimate emirate-specific people, institutions, authorities, territories, calendars, protocol, language, cultural practices, forms, rules, workflows, resources, events, marketplaces and reports.

## Event neutrality

Emirati is not an event-only application. Events, ceremonies, visits, journeys, transactions, incidents, council activities and spontaneous situations are all activity/situation compositions.

Examples include:

- Eid al-Fitr;
- Eid al-Adha;
- Sallah/Durbar;
- weddings and marriage ceremonies;
- funerals and condolence processes;
- trade and cultural fairs;
- family visits/homecomings;
- horse/rider participation and equipment markets;
- hospitality and accommodation;
- mobility and transport;
- emergency and incident response;
- council/institutional operations.

## Conformance

New Emirati requirements must first use existing OMNII objects, relationships and universal composition services. A new constitutional primitive is prohibited unless a genuine universal semantic gap is demonstrated and approved through the constitutional change model.

## Vendor independence

Emirati must be implementable without a paid/proprietary ECC or equivalent coordination product. Any provider is an optional adapter beneath the OMNII contracts.
